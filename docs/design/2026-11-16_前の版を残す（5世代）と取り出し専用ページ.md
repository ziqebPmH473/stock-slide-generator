# 前の版を残す（5世代）と、取り出し専用ページ（2026-11-16）

11/13 の作業（東証版）が、16 日の作業で上書きされて消えた。サーバーは上書きのたびに前の中身を消していて、「5世代残す」は入っていなかった。

## 1. 前の版を残す（`functions/api/state.js`・`functions/api/us-state.js`）

- 上書きするとき、前の目録を `h/<日付>/<rev>.json`（米国版は `us/<日付>/hist/<rev>.json`）に残す。東証版はその中身（`p/<日付>/…`）も消さない。
- 1日ごとに新しい順で **5世代**。ふつうの保存は **30分ごとに1世代**（数秒おきの保存で5世代を使い切らない）。
- 次のときは30分たっていなくても残し、5世代とは別に **3世代** まで残す（ふつうの保存で押し出されない）：
  基準日が変わる前／日（日本時間）が変わる前／別の端末で上書きされる前（force）／中身が大きく減る上書きの前（allowShrink）／前の版に戻す前。
- ⚙設定のサーバー保存の一覧で、各日の「前の版」→「この版に戻す」。今の版も前の版として残るので、戻したのを戻せる。
- API：`GET ?date=D&history=1`（一覧）、`GET ?date=D&rev=N`（その版）、`PUT ?date=D&restore=N`（戻す）。
- 米国版の音声は場面ごとに上書きされるので、前の版には入らない（作業の文章・動画のデータは入る）。米国版の画面にはまだ「戻す」ボタンが無い（API はある）。
- 2026-11-16 より前の版は残っていない（この仕組みを入れる前に消えている）。

## 2. 違う日の名前で保存しない（`index.html` の `ssgSyncPush`）

- 基準日の回（営業日）が保存先の日と違う → 黙って保存せず確認。OK＝基準日の回として保存（元の日はそのまま）／キャンセル・閉じた＝保存を止める。
- ページを開いたまま営業日が変わった（週末から開いたままのタブで月曜の作業など）→ 前の日の名前で保存し続けてよいか確認。キャンセル・閉じた＝保存を止める。

## 3. 取り出し専用ページ（`rescue.html`）

- `https://ssg-9506afd114d7.pages.dev/rescue.html` を開いて「💾 この端末の作業をファイルに出力」。
- ツール本体を動かさないので、日替わりの消去もサーバー保存もしない。中身は読むだけ（無いデータベースも作らない）。
- 出たファイルは ⚙設定の「取込」で開ける（東証版）。米国版を含む全部の localStorage も `rescue.allLocalStorage` に入る。
- 13 日の作業が残っていそうな端末は、**ツール（index.html）を開く前に** これで出力する（ツールを開くと、営業日が変わったので消える）。

## 4. 保存先をアカウントごとに分け、読み込みは手動に（2026-11-16 すみぽん「アカウントごとに保存先を分けて、手動で読み込むように。今回も AI に上書きされたから」）

- 保存先：R2 の `u/<アカウント>/` の下（東証版 `m/`・`p/`・`h/`、米国版 `us/`）。アカウントは Cloudflare Access のメールアドレス（ローカルは `local`）。`functions/_shared/store.js`。
- 書けるのは自分の保存先だけ。ほかのアカウントと、分ける前の共有の保存（R2 の直下。`from=_shared`）は **読むだけ**（`GET …&from=<アカウント>`）。共有の保存は消さずにそのまま残る（新しくは増えない。直近10日の掃除もしない）。
- `GET /api/state?owners=1`・`GET /api/us-state?owners=1`：保存のあるアカウントごとの日の一覧（自分が先頭、共有が最後）。
- **開いたときに自動で読み込まない。** 自分の保存に別の版があれば、画面の上に「読み込む／このまま続ける」を出すだけ。米国版も知らせるだけ。
- 中身が大きく減る保存を断ったとき、キャンセルで読み込むのをやめた（保存を止めるだけ）。
- ⚙設定の一覧：自分の保存は「開く」「前の版」→「この版に戻す」。ほかのアカウント・共有は「読み込む」「前の版」→「この版を読み込む」。読み込んだ内容は自分の保存先のその日として保存し、相手の保存は変えない。
- 週間まとめ：自分の保存を先に使い、自分に無い日はほかのアカウント・共有の保存から読む（読むだけ）。BGM の引き継ぎも、自分に無ければほかの保存から。
- 本番に出した直後は自分の保存先が空。続きから作業するときは、一覧の「共有（11/16 に分ける前の保存）」から読み込む。

## 5. データ取得のタイミングで世代を分ける（2026-11-16 すみぽん「データ取得をしたタイミングで世代を分けて。その後のデータは戻せるが、データ取得を過去データで再実行ができないから」）

- データ取得が成功したら、画面がすぐ（東証版0.5秒・米国版4秒後）`mark:'fetch'` を付けて保存する。東証版は、プロンプトをコピーする前でもここで保存を始める。
- サーバーは、そのとき今の版を「データ取得の前」として残す。取得の直後の版は、あとで上書きされるときに必ず「データ取得の直後」として残す（30分の間隔は関係なし）。
- 「データ取得の直後」は、5世代・ほかの3世代とは別に、1日ごとに5世代まで残す。⚙設定の「前の版」に理由として出る。
- 「データが空なら保存しない」は 2026-11-14（e09aa87）から入っている（画面は送らず、サーバーも量が0の作業は受け付けない）。

## 6. 取得したデータが何日のデータか（2026-11-16 すみぽん「取得したデータが16日13日のどっちのデータか見分けられないの？」「1 2 両方実装して」）

- **1. ページの表示から**（`functions/api/fetch-sources.js` の `parseAsOf`）：年月日＋時刻のすぐ後に「現在・更新・時点」があるものを読み、各ソースの `asOf {date, time}` に入れる。
  - 確かめたこと（11/16 17:48 に取得）：株探の寄与度・業種別「株価：2026年11月16日 16:00現在」、日経の上昇率・売買代金「2026年11月16日 15:50 更新」。
  - 野村（指数）はこの作業の環境から開けず未確認。見つからなかったときは、日付らしい文字を `dateHints` に残す（本番で一度取得して、取得結果の詳細で確かめる）。
- **2. 取得した時刻から**（ページに日付が無いとき・前の版で取ったデータ）：日本時間で、営業日の 15:30 以降＝その日の終値／9:00〜15:30＝その日の取引中の値／それ以外（朝・休みの日）＝直前の営業日。
- 画面（`index.html` の `autoDataDay`）：ページの日付があるソースのうち、いちばん多い日を「データの日」とする。取得結果の上に「📅 データの日：…」を出し、取引中の値・基準日の回と違う・ほかの日付のページがあるときは ⚠ を出す。
- 保存の前：データの日がサーバー保存の日と違えば、黙って保存せず確認。閉じた・キャンセル＝保存を止める。OK なら、同じ取得・同じ保存先のあいだは聞き直さない。
  - 例：13 日のデータを開いたまま基準日を 16 日にした → 16 日として保存しようとした時点で止まる。
- 週間まとめ：取得したデータの日が保存の日と違う日は使わない（11/13 の保存は 16 日に取得した中身なので外れる）。

## 7. 基準日を変えたら、その日を新しく始める（2026-11-16 すみぽん「基準日変えたら新規で始まるように。休場や時間外は加味し、実際に取得する日ベースで変わったら。前のデータを消すのではなく、違う日で始める。データがあれば、その日を開く」）

- **実際に取得する日**（`ssgEffDayOf`）：基準日の営業日（土日・祝日は直前の営業日）。基準日が今日で、今が 9:00 より前なら前の営業日（取れるのは前の営業日の終値なので）。サーバー保存の日もこれ。
  - 例：11/16（月）8:30 に基準日 11/16 → 11/13。9:30 → 11/16。基準日 11/15（日）→ 11/13。
- 基準日を変えて、この日が変わったときだけ動く（同じ日になる変え方では何もしない）：
  1. 変える前の日の作業を、変える前の日の保存として送る（まだ保存を始めていなくても送る）。保存できなかったときは「新しく始める（この端末のその日の作業は消える）／基準日を戻す」を聞く。閉じた・キャンセル＝基準日を戻す。
  2. 変えたあとの日の **自分の** 保存があれば、それを開く（ほかのアカウント・共有の保存は開かない。⚙設定の一覧から読み込む）。
  3. 無ければ、この端末の日ごとの作業を空にして（設定・BGM は残す。日替わりのリセットと同じ）、その日として読み込み直す。保存はデータ取得かプロンプトのコピーから。
- 前の日の保存は消さない。
- 確かめたこと（ローカル、実際の state.js を偽の R2 につないだ画面）：16 日に入力・保存 → 基準日 13 で空から始まる（16 はサーバーに残る）→ 13 に入力・保存 → 基準日 16 で 16 の作業が開く → 基準日 15（日）で 13 が開く。確認は1つも出なかった。9:00 前後の日の決まりも時刻を固定して確かめた。

## 8. 基準日の回と今取れるデータの日が違えば、データ取得をしない（2026-11-16 すみぽん「基準日と今日がちがえばデータ取得はしないのよね？」）

- 取得の前：基準日の回（`ssgBizDay`）と、今取れるデータの日（今日の `ssgEffDayOf`：営業日の 9:00 以降は今日、それ以外は直前の営業日）が違えば、取得しない（サーバーも呼ばない）。
- 取得の後：ページの表示のデータの日が基準日の回と違えば、取れた内容を使わない（いまの取得データはそのまま）。
- 東証版のデータ取得だけ。米国版は対象日をサーバーに渡して取るので対象外。

## 9. 週間まとめの前週末比（2026-11-16 すみぽん「指数はチャート用のデータを使えば？」「業種別と指数は、1週間前との比較を出力するか選べるように。初期値はする」）

- 前週末＝その週の月曜の前の営業日（`wkPrevWeekEnd`）。
- 指数の前週末の値：
  1. 日経平均・TOPIX：③動画のチャート用に株探から取った日足（各日の動画のデータの `points`。最長6か月）の、前週末の終値。
  2. グロース・スタンダードなど（日足は取っていない）：**前週末（前週の金曜。休みなら前の営業日）の保存**（すみぽん「前週金曜のデータを使え」）。取得したデータの日が合うものだけ。
  3. 2 が無い・正しくない（取得したデータの日が合わない）とき：**今週の最初の営業日（月曜。休みなら次の営業日）の「終値−前日比」から逆算**（すみぽん「正しくない場合には、取得日が正確なデータ（月曜か金曜）から逆算」）。その日の保存が無ければ出さない。
- 業種別の前週末の値：前週末の保存。無い・正しくないときは、今週の最初の営業日の取得データの「業種別指数−前日比」から逆算。どちらも無ければ週間のページを出さない。
- 前週末の保存は、前週の最後の営業日の日付の保存だけを見る（木曜などで代わりにしない）。
- 例：11/16〜20 の週は、11/13 の保存が 16 日の中身なので使わず、11/16（月）から逆算する。
- 週間まとめの画面に「前週末比を出す：□主要株価指数 □業種別」（初期値はどちらもチェックあり。毎回チェックありで始まる）。外すと、その場面の週間のページを作らず、表紙の「週間データ」の枠も出さない。

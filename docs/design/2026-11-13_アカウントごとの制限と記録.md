# アカウントごとの制限と操作の記録（2026-11-13）

AI（muse）にツールを操作させるため、アカウントごとに使える範囲を決め、使った記録を残す。**2026-11-13 実装済み**（本番に出すには `ADMIN_EMAILS` の登録が要る。手順は `docs/setup/2026-11-13_アカウントの追加と管理者の登録.md`）。

## すみぽんの指示（2026-11-13）

- muse に操作させる予定。アカウントによって機能を制限したい。
  - 例：音声生成は1日何回まで、時間帯で制限。
- 制限の上限と今日の回数は、自分のアカウントから見られる・設定できる。
- AI 用のアカウントの使用状況（操作の履歴）も見たい。
- 作業の保存先は**共有でよい**（AI が作ったものを自分が続きで使うため）。
- Cloudflare のログイン画面（Access）の「接続設定（RDP のクリップボード・ファイル）」は、この Web ツールには関係しないので触らない。

## しくみ

- 誰が使っているかは、Cloudflare Access が付けるメールアドレス（`Cf-Access-Authenticated-User-Email`）で見る。ローカル（localhost）は管理者扱い。
- `/api/〜` の入口（`functions/api/_middleware.js`）で、機能ごとに次を行う。
  1. 止める：使えない機能／時間帯の外／その日の上限に達した → 403・429 と、理由の文を返す（画面のエラー表示にそのまま出る）。
  2. 数える：成功したとき（HTTP 2xx かつ中身が `ok:false` でない）だけ、その日の回数を1つ増やす。文字数も足す。
     - **ボタン1回＝1回と数え、どのボタンの操作かを残す（2026-11-14 すみぽん「具体的にどのボタンか、ボタン単位で数えたい」）。**
       - 画面（`index.html` の先頭の小さなスクリプト）が、押したボタンの名前（`X-SSG-Button`）と、押した1回ごとの印（`X-SSG-Press`）を `/api` の呼び出しに付ける。
       - ボタンを押して1.5秒以内に `/api` を呼んだら、そのボタンの操作として始める。その後の呼び出し（動画の読み上げを場面ごとに呼ぶなど）は、次に別のボタンが操作を始めるまで同じ印を付け続ける。工程・タブの切り替えのように `/api` を呼ばないボタンは操作にならない（続いている操作を上書きしない）。動画の部品の中のボタンも、同じ仕組みで名前が付く。
       - サーバーは、同じ印の呼び出しを最初の1回だけ数える。ボタン別の回数（`buttons`）も残す。
       - 印の無い呼び出し（ボタンを押す前に自動で動いたもの、画面を通さない呼び出し）は「（ボタンなし・自動）」とし、3分以内に続いたものを1回にまとめる。
       - 上限に達していても、始まった操作（同じ印）の続きは最後まで通す（動画の途中の場面だけ止まらないように）。
       - 弱いところ：ボタンを押したあとに自動で動いた呼び出しは、直前に押したボタンの操作として付く。また、操作の途中で別のボタン（`/api` を呼ぶもの）を押すと、その後の呼び出しはそちらの名前になる。
  3. 記録：成功・失敗・止めたを含めて、1回ずつ残す（時刻・アカウント・ボタン・機能・結果・モデル・声・文字数・かかった秒）。頼んだ本文は残さない。
- 管理者は環境変数 `ADMIN_EMAILS`（カンマ区切り）。管理者は制限を受けない。
  - `ADMIN_EMAILS` が未設定のあいだは、全員を今までどおり（制限なし・記録だけ）にし、管理画面は誰も開けない。**muse を Access に入れる前に `ADMIN_EMAILS` を登録すること。**
- R2（`STATE`）が紐づいていないときは何もしない（今までどおり）。

### 文章の AI と「AI を直接呼ぶ」

- 今は Gemini の待ち時間の問題（Cloudflare が125秒で切る）を避けるため、画面に AI のキーを渡し、ブラウザから直接 Gemini・Claude を呼んでいる（`/api/gemini-key`・`aiFetch`）。
- キーを渡すと画面から直接呼べるので、回数を数えられず、上限も効かない。
- そこで、管理者以外は、管理画面の「AI を直接呼ぶ（キーを渡す）」をオンにしたアカウントにだけキーを渡す（初期値はオフ）。
- オフのアカウントは `/api/gemini-key` が 403 を返し、画面は自動で `/api/analyze`（サーバー経由。数えられる）を使う。
  - その代わり、考える時間の長いモデル（3.8 Flash など）が重い作業で切られやすい（524）。切られたら下のモデルへ自動で降りる。
  - 困るようなら、サーバー側で待つ仕組み（例：Durable Objects や、結果を R2 に置いて画面が取りに来る形）を作る。**未着手。**

### 置き場所（R2 の `STATE`）

作業の保存（`m/`・`p/`）とは別の `acl/` の下に置く。作業の保存は全員で共有のまま（アカウントで分けない）。

- `acl/config.json`：アカウントごとの設定（管理画面で変える）
  - `users`：`{ メール: { label, directAI, hours: {from, to} | null, limits: {機能: 回数}, disabled: [機能] } }`
  - `default`：`users` に無いアカウント全員の設定
- `acl/usage/<日本時間の日付>/<メール>.json`：その日の操作の回数（`ai` など）・呼び出しの回数（`aiCalls`）・文字数（`aiChars`）・最後に呼んだ時刻（`aiLast`）・最近の印（`aiPresses`）・ボタン別の回数（`buttons`：`{ "機能|ボタン": { n, calls } }`）
- `acl/log/<日本時間の日付>/<時刻>-<乱数>`：1回の操作の記録（中身は customMetadata。一覧を取るだけで読める）
- 記録と回数は 30 日分残す（管理画面を開いたときに、古いものを消す）。
- R2 は足し算を一度にできないので、同時に何本も叩かれると回数が1回ぶんずれることがある（実用上は問題ない）。

## 管理画面（`/admin`）

- ⚙設定の「アカウント管理 → 👤 開く」から開く。開けるのは `ADMIN_EMAILS` の人とローカルだけ。
- アカウントごとに：名前（例：muse）、AI を直接呼ぶ、使える時間（日本時間。○時〜○時の前まで。日をまたぐ指定も可）、機能ごとの「使う」と1日の上限（空欄は無制限、0 は使えない）、今日の回数と文字数。
- 「その他のアカウント」：設定に無いアカウント全員に効く設定。
- 管理者（制限なし）の今日の回数も見るだけ出す。
- 今日のボタン別の回数：アカウントごとに、ボタン・機能・回数・呼び出しの回数。
- 操作の記録：日付・アカウント・機能・ボタンで絞って、新しい順に最大500件。
- 保存はすぐに効く。

## 確かめたこと（2026-11-13、ローカルの wrangler pages dev ＋ R2）

- 管理者は管理画面を開ける。管理者以外は「このアカウントは管理者ではありません」。
- 止めた機能（画像）・上限0（音声）・上限1の2回目（データ取得）・時間帯の外が、それぞれ理由つきで止まる。
- 中身が `ok:false` の答えは数えない。記録には「失敗」と理由が残る。
- 「AI を直接呼ぶ」がオフのアカウントにはキーを渡さない。オンなら今までどおり `/api/gemini-key` に進む。
- ツール本体の画面はエラーなく開き、作業の保存（`/api/state`）も今までどおり使える。
- 本番（Cloudflare Access の付けるメールアドレス）では未確認。`ADMIN_EMAILS` を登録したあとに確かめる。

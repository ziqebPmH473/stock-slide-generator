# Gemini を画面から直接呼ぶ／別の端末で続きから開く（2026-10-18）

前提：本番（`ssg-9506afd114d7.pages.dev` と `*.ssg-9506afd114d7.pages.dev`）に Cloudflare Access のログインが掛かっていること（docs/setup/2026-10-18_Cloudflare Access（ログイン）.md）。

## Gemini を画面から直接呼ぶ
- 起きていたこと：`/api/analyze`（Pages Function）から Google への呼び出しは、最初の返事が約125秒までに来ないと Cloudflare に切られる（HTTP 524）。考える時間の長い 3.8・3.7 Flash が重い作業で毎回切られて降格していた。stream にしても直らなかった（決算ツールで確認済み）。
- `functions/api/gemini-key.js`：環境変数 `GEMINI_API_KEY` を画面に渡す。本番URLでログイン済み（`Cf-Access-Jwt-Assertion` あり）と localhost だけ。デプロイごとの別URLには渡さない。
- `index.html` の `aiKey()`・`aiFetch()`：`fetch('/api/analyze',…)` と同じ呼び方・同じ返し方。組み立てと下のモデルへの切り替え（各モデル1回リトライ）は analyze.js と同じ。キーはメモリにだけ持ち、`x-goog-api-key` ヘッダーで渡す。受け取れないときは `/api/analyze` へ（analyze.js は予備として残す）。
- analyze.js を直すときは aiFetch も同じように直す（2か所にある）。
- 読み上げ（tts.js）・画像（image.js）は今までどおりサーバー経由。

## 別の端末で続きから開く
- 保存先：R2 バケット `stock-slide-generator-state`（Pages のバインディング名 `STATE`）。`functions/api/state.js`。
- 1日＝目録 `m/<日付>.json`＋中身 `p/<日付>/<名前>`。中身は localStorage の `ssg_*` のまとめ1つと、IndexedDB（ssg-images・kessan-viz-audio・ssg-bgm）の1件ずつ。名前は中身から作るので、変わったものだけ送る。
- 目録は rev で上書き事故を防ぐ（別の端末が先に保存していたら 409 → どちらを採るか聞く）。新しい順に5日分だけ残す。
- 保存を始めるのは、その日に最初にプロンプトをコピーしたとき（`autoClip`・`apCopyWithFeedback` → `ssgSyncStart`）。日付が入っただけでは保存しない。その後は欄の保存のたび（3秒待ち）と20秒ごと・画面を離れたときに送る。
- 開いたとき・画面が表に出たとき：その日の保存がサーバーにあって rev が違えば、それに置き換えて読み込み直す（この端末にまだ送っていない変更があるときは聞く）。今日の保存が無ければ（日が変わった）今までどおり新しく始める。
- 端末側の状態は localStorage の `ssg_sync`（`{day, rev, parts, baseDate, on, force}`）。出力・取込・サーバー保存の対象から外す（`SSG_SYNC_SKIP`）。
- ⚙設定の「サーバー保存」に直近5日の一覧。「開く」で前の日に戻せる（その日のうちは、開いた日の保存に入る）。
- 「📥 取込」したときは、その内容を今日の保存としてサーバーを上書きする。
- ローカルで試すとき：`npx wrangler pages dev . --r2 STATE --compatibility-date 2026-06-01`（.claude/launch.json の `pages-dev`）。localhost と 127.0.0.1 は保存が別なので、2台の端末の代わりになる。

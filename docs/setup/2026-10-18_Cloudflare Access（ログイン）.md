# 東証ツールに Cloudflare Access でログインを掛ける（＋別の端末で続きを開くための保存先）

東証ツールの本番URLに、決算ツールと同じログインを掛ける手順です。あわせて、別の端末でも続きから開けるようにするための保存先（R2）も作ります。上から順にそのまま進めれば終わります（10 分ほど）。

- なぜ要るか：
  - Gemini を画面から直接呼ぶ形（3.8 Flash が 125 秒で切られる問題の対策）では、APIキーを画面に渡します。ログインが無いと、URL を知っている人なら誰でもキーを受け取れてしまいます（今の `/api/analyze` も、ログインが無いので誰でも使える状態です）。
  - 作業内容をサーバーに保存するので、それもログインした本人だけが見られるようにします。
- 本番URL: `https://ssg-9506afd114d7.pages.dev/`
- Pages のプロジェクト名: `ssg-9506afd114d7`
  - 似た名前の別プロジェクト（`stock-analysis-slide-〜` など）ではありません。
- Zero Trust のチームは決算ツールで作った `naresla` をそのまま使います（新しく作らない）。
- ログインのポリシーも決算ツールの `me` をそのまま使います。

---

## 1. Access のアプリケーションを追加する（ログインを掛ける）

1. 開く: https://one.dash.cloudflare.com/
   - チームを選ぶ画面が出たら `naresla` を選ぶ。
2. 左のメニューの「アクセス（Access）」→「アプリケーション（Applications）」を開く。
   - 決算ツール用の `kessan-tool` が並んでいるはずです。それとは別に、もう1つ作ります（`kessan-tool` は触らない）。
3. 「アプリケーションを追加（Add an application）」を押す。
   - 「セルフホストとプライベート」のタブのまま、右下の「セルフホストとプライベートで続行」を押す。
   - 中ほどの「プライベート宛先／Workers／パブリックDNS／サービス認証」は図の例を切り替えるだけなので、どれでもよいです。
   - 画面が古い形の場合は「セルフホスト（Self-hosted）」を選ぶ。
4. 次のように入れる。
   - アプリケーション名:
     ```
     stock-slide-generator
     ```
   - セッション期間（Session Duration）: `1 month`（いちばん長いもの。端末ごとに月1回のログインで済みます）
   - 「宛先」の「パブリックホスト名」の行に、本番のホスト名を入れる。
     - サブドメイン：空のまま
     - ドメイン：プルダウンから `ssg-9506afd114d7.pages.dev` を選ぶ（出ない場合は「カスタム入力に切り替える」で貼る）
     - パス：空のまま
   - 「＋ パブリック ホスト名を追加」を押して2行目を増やし、デプロイごとの別URL（`〜.ssg-9506afd114d7.pages.dev`）にもログインを掛ける。
     - サブドメイン：
       ```
       *
       ```
     - ドメイン：1行目と同じ `ssg-9506afd114d7.pages.dev`
     - パス：空のまま
     - `*` が入らない・エラーになる場合は、2行目を消して先へ進み、終わったときにそう伝えてください（こちらのコードで、別URLではキーも保存内容も渡さないようにしてあります）。
   - パスの欄は空のままにする（サイト全体＝画面と `/api/〜` のすべてに掛かります）。
   - 「次へ（Next）」
5. ポリシーを選ぶ。
   - 「既存のポリシーを選択（Select existing policies）」で、決算ツールで作った `me` にチェックを入れる。
   - `me` が出てこない場合だけ、新しく作る：
     - ポリシー名: `me`
     - アクション: `許可（Allow）`
     - ルールの「含める（Include）」→ セレクター `メール（Emails）` → 値に決算ツールのログインと同じメールアドレスを入れる。
   - 「次へ（Next）」
6. ログイン方法（Login methods）は決算ツールと同じものが選ばれているはずです。そのまま「次へ（Next）」→「保存（Save）」。

## 2. 作業内容の保存先（R2 バケット）を作る

1. 開く: https://dash.cloudflare.com/?to=/:account/r2/overview
2. 「バケットを作成する（Create bucket）」を押す。
3. バケット名に次を入れる。
   ```
   stock-slide-generator-state
   ```
   - 決算ツールの `kessan-tool-media` とは別に作ります（使い回さない）。
4. 場所は「自動（Automatic）」のまま。「バケットを作成する（Create bucket）」を押す。

## 3. Pages プロジェクトに紐づける

1. 開く: https://dash.cloudflare.com/?to=/:account/pages/view/ssg-9506afd114d7
   - 開けない場合は https://dash.cloudflare.com/?to=/:account/workers-and-pages を開き、一覧から `ssg-9506afd114d7` を選ぶ。
2. 上の「設定（Settings）」→ 左の「バインディング（Bindings）」を開く。
   - 見当たらない場合は「設定」→「関数（Functions）」の中にあります。
   - 「本番（Production）」と「プレビュー（Preview）」の切り替えがある場合は「本番」の方で行います。
3. 「追加（Add）」→「R2 バケット（R2 bucket）」を選ぶ。
   - 変数名（Variable name）:
     ```
     STATE
     ```
     （大文字。これ以外の名前だとツールが見つけられません）
   - R2 バケット: `stock-slide-generator-state`
   - 「保存（Save）」
4. 同じ「設定」の「変数とシークレット（Variables and Secrets）」に `GEMINI_API_KEY` があることだけ確かめる（今の AI のボタンが使っているものです。触らない）。
5. 紐づけは次のデプロイから効きます。こちらが次に push するので、再デプロイはしなくて大丈夫です。

## 4. 確かめる

1. ブラウザ（ふだん使っていない端末か、シークレットウィンドウがわかりやすい）で https://ssg-9506afd114d7.pages.dev/ を開く。
2. ログイン画面が出て、ログイン後にいつもの東証ツールが開けば完了です。

### 注意（前に困ったところ）

- Pages プロジェクトの設定にある「アクセスポリシーを有効化（Enable access policy）」は**押さない**でください。デプロイごとの別URLは手順1-4の2つ目のホスト名で守ります。あのボタンは別のアプリケーションを勝手に作り、以前「テスト環境だけ入れない」となった原因です。
- Access を掛けると、ブラウザ以外からの `/api/〜` 呼び出しも止まります。このツールにはそれが無いので問題ありません。
- ローカルの確認（localhost）には Access は掛かりません。今までどおり動きます。

## 終わったら

チャットで「**東証ツールに Access を掛けた**」と伝えてください。2つ目のホスト名（`*.ssg-9506afd114d7.pages.dev`）が入ったかどうかも一言添えてください。

こちらで引き受けること:
- ログインしないと開けないことの確認（画面・`/api/analyze`・デプロイごとの別URL）
- APIキーを渡す口（`/api/gemini-key`）と、画面から Gemini を直接呼ぶ形、別の端末で続きを開く保存（`/api/state`）を push（再デプロイ）
- 本番での動作確認と、3.8 の重い作業が降格せずに通るかを試す手順のご案内

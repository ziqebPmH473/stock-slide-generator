## 1. 自分を管理者にする（環境変数 ADMIN_EMAILS）

1. 開く: https://dash.cloudflare.com/?to=/:account/pages/view/ssg-9506afd114d7
2. 上の「設定（Settings）」→「変数とシークレット（Variables and Secrets）」を開く。
   - 「本番（Production）」と「プレビュー（Preview）」の切り替えがある場合は「本番」の方で行います。
3. 「追加（Add）」を押し、次のように入れる。
   - 種類（Type）: `テキスト（Text）`
   - 変数名（Variable name）:
     ```
     ADMIN_EMAILS
     ```
   - 値（Value）: 自分がツールにログインするときのメールアドレス（複数ならカンマで区切る）
4. 「保存（Save）」。
5. 次のデプロイから効きます。すぐに効かせたいときは「デプロイ（Deployments）」の一番上の「…」→「デプロイを再試行（Retry deployment）」。
6. 確かめる：ツールの ⚙設定 →「アカウント管理」の「👤 開く」で管理画面が開けば完了です。
   - 「管理者が決まっていません」と出る：変数がまだ効いていない（5 を行う）か、名前の綴りが違う。
   - 「このアカウントは管理者ではありません」と出る：値のメールアドレスが、ログインしたアドレスと違う（下に出る「ログイン中：」のアドレスを入れる）。

## 2. ログインできる人を足す（Cloudflare Access）

注意：今のポリシー `me` は**決算ツールと共有**です。`me` にアドレスを足すと決算ツールにも入れてしまうので、東証ツールだけの新しいポリシーを作ります。

1. 開く: https://one.dash.cloudflare.com/
   - チームを選ぶ画面が出たら `naresla` を選ぶ。
2. 左のメニューの「アクセス（Access）」→「アプリケーション（Applications）」を開く。
3. `stock-slide-generator` の「…」→「編集（Edit）」を押す。
4. 「ポリシー（Policies）」のところで「新しいポリシーを作成（Create new policy）」を押す（別のタブで開いた場合は、作ったあと元のタブに戻る）。
   - ポリシー名:
     ```
     ssg-muse
     ```
   - アクション: `許可（Allow）`
   - ルールの「含める（Include）」→ セレクター `メール（Emails）` → 値に muse がログインに使うメールアドレス
   - 「保存（Save）」
5. アプリケーションの画面に戻り、ポリシーの一覧で `me` と `ssg-muse` の**両方**にチェックが入っていることを確かめて「保存（Save）」。
6. 「接続設定」（リモートデスクトップのクリップボード・ファイル）は触らない。この Web ツールには関係しません。

ログインの方法による違い：
- ワンタイムPIN（メールに届くコード）の場合：muse がそのメールを受け取れる必要があります。
- Google ログインの場合：muse 用の Google アカウントが要ります。
- 人数は Zero Trust の無料枠（50人）に収まります。

## 3. muse の制限を決める（管理画面）

1. ツールの ⚙設定 →「アカウント管理」の「👤 開く」。
2. 下の「追加するメールアドレス」に muse のアドレスを入れて「＋ アカウントを追加」。
3. 名前（例：`muse`）、使える時間、機能ごとの「使う」と1日の上限を決める。
   - 上限は空欄で無制限、0 で使えない。ボタン1回を1回と数えます（3分以内に続いた呼び出しはまとめる）。
   - 「AI を直接呼ぶ」はオフのままがおすすめ（オンにすると文章の AI を数えられず、上限も効きません）。オフだと、考える時間の長いモデルが重い作業で切られて下のモデルに降りることがあります。
4. 「💾 設定を保存」。すぐに効きます。
5. muse で一度ログインして何か操作し、管理画面の「操作の記録」に出ることを確かめる。

## 終わったら

チャットで「**ADMIN_EMAILS を入れた**」「**muse を Access に足した**」と伝えてください。本番で、メールアドレスで見分けられているか・止まるか・記録に残るかを一緒に確かめます。
